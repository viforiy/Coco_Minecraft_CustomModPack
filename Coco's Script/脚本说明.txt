Coco's 整合包 · 脚本目录说明
==============================================================================

一. 目录约定
------------------------------------------------------------------------------
  整合包根目录(实例目录)   : 本文件夹的上一级, 里面有 mods\ config\ options.txt 等
  脚本目录                : 本文件夹 Coco's Script\
  数据目录(不随整合包)     : %LOCALAPPDATA%\CocoPackwiz\  (元数据仓 meta\ 日志 logs\
                            工具 tools\ 备份 backup\ 便携 Java jre\)
  分类快照(机器可读)       : %LOCALAPPDATA%\CocoPackwiz\mod-classify.tsv
  裁剪清单与分类报告       : 实例目录 [客户端]模组裁剪清单.txt / [客户端]模组分类报告.txt
  配置文件                : 本文件夹 mod更新源.cfg (实例根目录放一份也认)

  所有脚本都从自己的位置往上找"含 mods 的目录"当实例目录(最多 3 层), 所以脚本
  放在本文件夹里(当前布局)或直接放实例根目录(老布局)都能跑。
  想强行指定: 任一 ps1 都能加 -GameDir "<实例目录>", 或设环境变量 COCO_GAME_DIR。


二. 执行链(正常启动游戏时)
------------------------------------------------------------------------------
  PCL - 版本设置 - 设置 - 高级选项 - 启动前执行指令 里只放一条:

    call "{verpath}\Coco's Script\[客户端]mod更新脚本.bat" "$INST_JAVA" && call "{verpath}\Coco's Script\[客户端]mod后处理修复脚本.bat" -Quiet

  这条命令由 [客户端]mod更新脚本.bat 每次跑完自动重新生成, 并写进实例目录的
  PCL启动前命令.txt 顺便复制到剪贴板, 换机器/换路径直接粘贴即可。

  [客户端]mod更新脚本.bat
      Java 21 -> git 同步元数据仓 -> packwiz refresh
      -> 4.5  裁剪(mod裁剪脚本.bat, 按清单裁客户端模组)
      -> 6    packwiz 安装器同步 mods
      -> 6.5  脚本归位(packwiz 装到根目录的 ps1/bat 挪进本文件夹, 旧名自动清理)
      -> 7    汇总变动 -> 8 重写 PCL 启动前命令

  [客户端]mod后处理修复脚本.bat
      依次 call: fix-grand-teleport-version / mcef-block-download /
                 muoniumconfig-patch-soundevent, 全部幂等。


三. 各脚本一览
------------------------------------------------------------------------------
  文件                                    作用                            用法
  --------------------------------------  ------------------------------  --------------------
  [客户端]mod更新脚本.bat                 更新 mods(主入口)               双击 / PCL 启动前
  mod裁剪脚本.bat / mods-clip.ps1         按清单裁客户端模组              双击交互挑选
  [客户端]mod后处理修复脚本.bat           跑下面三个修复                  PCL 启动前第二段
  fix-grand-teleport-version.bat .ps1     Grand Teleport 版本号修正       单独修一个 mod
  mcef-block-download.bat .ps1            MCEF 不再联网下依赖             单独修一个 mod
  muoniumconfig-patch-soundevent.bat .ps1 MuoniumConfig 声音事件补丁      单独修一个 mod
  packwiz-manage-grand-teleport.bat .ps1  把修好的 jar 托管进元数据仓     维护仓库时手动跑
  一键切换NeoForge版本.bat                换 NeoForge 版本               菜单式, 手动跑
  NeoForgeSwitch.ps1                      上一条的实际逻辑(3400 行)       跑完要重启 PCL2
  mod更新源.cfg                           元数据仓地址与各项开关          手改, 下次运行生效


四. 统一约定(改脚本请沿用)
------------------------------------------------------------------------------
  编码      .bat = GBK(936) 且首两行 @echo off / chcp 936
            .ps1 = UTF-8 带 BOM, 首行 #requires -version 5
            脚本写出的 .txt/.cfg/.log = GBK, 与 PCL启动前命令.txt 一致
            说明: 头部注释里的中文在错误代码页下可能被误解析, 所以每个 bat 都
                  把 chcp 936 放在第 2 行, 后面才出现中文
  输出前缀  [信息] [完成] [警告] [错误] [跳过]
            -Quiet 时只留 完成/警告/错误/跳过; 彩色只在主更新脚本里保留
  参数      所有 bat 都支持 --help; 维修类支持 -Quiet; 所有 ps1 支持 -GameDir
  返回码    0 = 正常 / 已是最新 / 没装这个 mod      1 = 出错      (NeoForge 切换 2=参数错)
  幂等      每个修复脚本都先判断"要不要改", 已修过的直接跳过, 不重复写盘
  回滚      改动前都会留 .bak-*; packwiz 那条线靠 git reset, 清单说了算


五. 与元数据仓的关系(重要)
------------------------------------------------------------------------------
  元数据仓(main 分支)里的脚本也放在 Coco's Script\ 下, 其中 *.ps1 由 packwiz
  安装器直接装进本文件夹, *.bat 被 .packwizignore 排除(靠仓库检出 / 一键部署带过来)。
  一句话: ps1 以仓库为准, bat 以本机为准。

  第 6.5 步"脚本归位"兜两件事:
      - 老仓库把 ps1 装在实例根目录 -> 挪进本文件夹
        (没有同名就收下 / 相同就删根目录那份 / 不同就保留本机这份并提示)
      - 改过名的旧文件(见第七节)只要新名字那份在, 旧名字的删掉, 本文件夹和根目录都管

  仓库里还叫旧名的话, 每次启动会重下一次旧名 ps1 再被删掉(约 46KB)。要彻底停掉,
  在仓库 clones 里改名并推送:
      git mv "[客户端]mod前置裁剪脚本.bat" "mod裁剪脚本.bat"
      git mv "[客户端]mod前置裁剪脚本.ps1" "mods-clip.ps1"
      packwiz refresh
      git add -A && git commit -m "裁剪脚本改名" && git push


六. 常见问题
------------------------------------------------------------------------------
  中文乱码          控制台代码页不是 936。本目录 bat 都自带 chcp 936,
                    从 PCL 启动链进来就是 936; 在 UTF-8 终端里直接跑 ps1 会乱,
                    换成 cmd 或默认代码页的 powershell 即可。
  [跳过] 找不到 jar  对应 mod 没装或被裁掉了, 正常现象, 返回码仍是 0。
  找不到实例目录      脚本被移出整合包了。用 -GameDir 指定, 或把整个文件夹放回
                    <实例目录>\Coco's Script\。
  裁剪不生效          看 [客户端]模组分类报告.txt 里"索引刷新"一行;
                    没有 packwiz 时只出报告不改元数据(防安装器 404)。
  "删除改名前的旧文件"  正常: 仓库里那份还叫旧名, 6.5 把它删了。按第五节 git mv 收尾。
  "N 个脚本与包里的不同"  本机这份是改过的, 包里那份是旧的。把本机这份推到元数据仓
                    对应分支后提示自然消失。
  找不到 NeoForge 版本  NeoForgeSwitch 会沿脚本位置向上找 .minecraft, 并把结果记在
                    本文件夹 配置.cfg; 找不到就用 -PickMcDir 手选。
